# Российский сервер заявок (опционально)

**Не разворачивайте этот сервер на Vercel или зарубежной площадке**, если он будет принимать данные граждан РФ. Основной сайт может быть статическим на Vercel, но форма должна отправлять данные непосредственно на российскую инфраструктуру оператора с учётом применимых требований локализации, безопасности и трансграничной передачи. Это образец без коммерческих гарантий.

1. Выберите российский сервер/сервис с подтверждённым размещением и договором с оператором данных. Настройте HTTPS (например, Nginx) и резервирование/логи без персональных данных.
2. В окружении сервера задайте `SITE_ORIGIN=https://example.ru`, `LEAD_WEBHOOK_URL=https://<доверенный-получатель-в-РФ>/leads`, `LEAD_WEBHOOK_SECRET=...`. Вебхук должен фактически сохранять заявку в РФ и отвечать 2xx **только после успешной записи/доставки**.
3. Запустите `node backend-russia/server.mjs`, проксируйте `/leads` с публичного HTTPS домена на `127.0.0.1:8080`, примените распределённое ограничение запросов на nginx/WAF (локальный Map не распределён и не защищает от массированной атаки).
4. В переменных сборки фронтенда: `VITE_LEAD_ENDPOINT=https://api.example.ru/leads`, `VITE_LEAD_FORM_ENABLED=true`. Укажите реальные проверенные `site.legal.*`, затем разрешите API origin в `connect-src` CSP. До этого форма должна оставаться отключённой.
5. Проверьте тестовой заявкой результат у получателя. **Не отправляйте настоящие ПД в тесты.**

Важно: consent и privacy — заготовки; требуется правовая проверка конкретного оператора, порядка уведомления РКН и процессов передачи. На реальном проекте необходимо обеспечить мониторинг, распределённый rate limit, надёжную доставку и повтор при временных сбоях.
