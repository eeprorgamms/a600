# A500 — техническое задание и план модернизации
Дата аудита: 20.11.2026. Репозиторий: eeprorgamms/a600; исходная ветка: main. Рабочая ветка: a500-modernization-review.

## 0. Принципы
- Сохраняем текущий дизайн и пять основных страниц: /, /services, /pricing, /about, /contacts.
- Сначала исправляем работоспособность, безопасность и данные. Визуальный редизайн — отдельный этап.
- Не изменяем production без согласования. Все изменения — в отдельной ветке и на тестовом развёртывании.
- Никаких платных сервисов без разрешения.
- Никаких неподтверждённых цен, отзывов, рейтингов, телефонов или графика работы.
- Публичная доступность кода не означает права на изображения, шрифты и отзывы. Проверить коммерческие лицензии перед продажей.

## 2. Приоритет P0 — не вводить клиента в заблуждение
- Форма: блокировать повторную отправку, проверять обязательные поля, отправлять JSON на same-origin /api/lead; показывать успех только при подтверждённом успешном ответе, ошибки — явно. Не логировать персональные данные в консоль.
- Сервер: /api/lead с серверной валидацией (строки, длины, телефон), лимитами тела, rate limiting (с устойчивым хранилищем/edge gateway при реальном развёртывании), honeypot, безопасным учётом ошибок, журналированием без ПД.
- Доставка: согласовать способ получения заявок в инфраструктуре, подходящей по российскому законодательству. Не подключать Telegram/иностранное хранилище ПД без оценки трансграничной передачи и локализации. Секреты — только серверные env.
- До подключения реального обработчика форма не должна обещать отправку; можно оставить звонок как надёжный основной канал.
- Выключить публичный /admin; убрать ссылку в footer. Не хранить заявки в localStorage и не показывать их в открытой панели.
- Календарь: «Предпочтительные дата и время», интеграция в payload и явное пояснение «Время подтверждается после звонка»; либо убрать до рабочего подключения.

Критерии: реальная тестовая заявка достигает согласованного получателя; при ошибке отправки показывается ошибка; секретов нет в bundle; повторные клики не дублируют отправку; /admin не открывает список заявок.

## 4. Приоритет P2 — SEO, безопасность, доступность и скорость
- Перейти с HashRouter на BrowserRouter, настроить rewrite SPA на index.html на Vercel. Проверить прямое открытие /services, /pricing, /about, /contacts.
- Динамические title/description, canonical, OG, robots.txt, sitemap.xml с реальным production origin, корректные alt; структурированные данные LocalBusiness только по подтверждённой информации.
- Настроить HTTPS на домене, заголовки X-Content-Type-Options, Referrer-Policy, Permissions-Policy, уместную CSP (учесть карты, шрифты, картинки и API; тестировать перед строгой политикой).
- Исключить опасный HTML, внешние скрипты без необходимости, проверить зависимости через npm audit, pinning/lockfile.
- Проверить мобильное меню, кликабельные зоны, фокус клавиатуры, семантику; Lighthouse на реальных устройствах/в браузере, Core Web Vitals без неподтверждённых обещаний.
- Изображения: оптимизация, лицензионная чистота, запрет зависимости от нестабильных AI image URLs.
- Подготовить шаблон политики ПД, поля оператора, отдельное согласие там, где требуется, управление необязательными cookies/аналитикой по фактическому применению; правовая проверка под клиента и поставщиков услуг обязательна.

Критерии: нет ошибок сборки, 404 на несуществующих маршрутах, работающие прямые URL и метаданные, нет console errors на основных сценариях.

## 5. Архитектурное и коммерческое решение
- Сохраняем React + TypeScript + Vite + Tailwind, существующие страницы и визуальную систему.
- Сайт за 24 900 ₽ не включает CRM, реальное управление занятостью боксов, платёжную систему, личный кабинет. Любая новая интеграция — отдельная оценка.
- Разработка на ветках; передача заказчику с правомерным использованием шаблонных компонентов и лицензий — урегулировать в договоре.
- Руководство по конфигурации, настройке домена/хостинга, секретам, заявкам, проверке и откату.

## 6. Очерёдность работ
1. P0: формы, серверный маршрут, отключение ложной «записи» и публичного admin.
2. P1: реальная карточка организации, единый конфиг и прайс, работоспособность ссылок.
3. P2: маршруты/SEO/заголовки/защита/доступность.
4. E2E-проверка на preview Vercel с тестовой отправкой; checklist desktop/mobile.
5. После подтверждения — отдельно UI/UX-дизайн и фотоконтент.
6. Production publish — только после отдельного разрешения заказчика.

## 7. Что остаётся согласовать до выпуска в продажу

- Хостинг/домен каждого заказчика и ответственное лицо за поддержку.
