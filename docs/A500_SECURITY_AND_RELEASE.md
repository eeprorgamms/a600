# A500 — безопасность и контроль качества

Дата аудита: 24.11.2026. Рабочая ветка: \`a500-modernization-review\`.
Этот документ описывает текущие ограничения и проверки; отсутствие замечаний в отдельных проверках не означает абсолютную защищённость.

## Архитектура и границы доверия

Основная часть — статический React/Vite-сайт. От посетителя не принимаются данные через публичную форму, не используются платёжные данные, аккаунты или админ-панель. Кнопки ведут на страницы, на звонок и в Яндекс Карты. Это существенно снижает серверную поверхность атаки.

Остаточные риски: сторонние изображения Unsplash, веб-шрифты Google Fonts, встроенный виджет Яндекс Карт; их доступность, политика данных и сроки хранения контролируются соответствующими провайдерами. Не добавлять внешние скрипты без анализа.

Папка \`backend-russia/\` содержит отдельный опциональный серверный пример. Он не подключён к публичным страницам. **Нельзя включать приём заявок без отдельной проверки конфигурации, защиты от злоупотреблений, политики ПДн и тестирования сервера**.

## HTTP-защита

\`vercel.json\` настраивает:
- CSP: скрипты только собственного домена, запрет \`unsafe-eval\`, \`object-src 'none'\`, \`frame-ancestors 'none'\`, \`base-uri 'self'\`, \`form-action 'self'\`, ограничение изображений, шрифтов и фреймов;
- Strict-Transport-Security (HTTPS);
- X-Content-Type-Options, X-Frame-Options, Referrer-Policy;
- Permissions-Policy, Cross-Origin-Opener-Policy и Cross-Origin-Resource-Policy;
- \`Cache-Control: no-store\` для путей \`/api/\`.

Исключение: \`style-src 'unsafe-inline'\` сохраняется для существующих inline-стилей React. Для более строгой политики потребуется удалить inline-стили и перейти к CSS-классам.

## Развёртывание

Автоматический деплой Git-пушей отключён параметром \`git.deploymentEnabled=false\`. Рабочую ветку не сливать с \`main\` без явного согласования. Перед единственным ручным деплоем:
1. Проверить информацию о ценах, телефоне и адресе по официальной карточке.
2. \`npm ci\`.
3. \`npm run check\` — TypeScript + статические проверки.
4. \`npm audit --audit-level=moderate\` — проверить критичные зависимости и оценить найденные проблемы.
5. \`npm run build\` — Vite + SEO + пререндер всех пяти страниц.
6. Через браузер проверить ширины 320, 375, 390, 428, 768, 1024, 1366, 1920, 2560 px; каждый маршрут, галерею, стрелки и Escape, прокрутку, меню, телефон, карту.
7. Для повторяемого теста можно запустить `node scripts/browser-qa.mjs` после временной установки Playwright и запуска `npm run dev`. В DevTools проверить консоль, ошибки загрузки, CSP, заголовки ответа, отсутствие горизонтальной прокрутки, клавиатурную навигацию и режим reduced motion.
8. Ручной preview deploy только после одобрения, затем повторная проверка URL и HTTPS-заголовков.

## Оставшиеся ограничения

- Нельзя гарантировать совместимость со *всеми* устройствами и браузерами без физических тестов.
- Веб-фотографии и шрифты зависят от третьих сторон.
- Цены взяты из публичной карточки, а не из подписанного прайс-листа.
- Реальные авторские фотографии A500 могут быть добавлены в галерею после получения разрешения.
- CSP style-src пока не полностью исключает inline-стили.
